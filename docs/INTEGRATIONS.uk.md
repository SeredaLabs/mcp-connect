# Адаптери клієнтських інтеграцій

🌐 [English](INTEGRATIONS.md) · **Українська**

[← Огляд](INSTALL.uk.md) · [Збирання та перевірки](BUILD.uk.md) · [Безпека](SECURITY.uk.md)

MCP Connect реєструє клієнтів через невеликі адаптери в `internal/core`. Координатор не читає формати постачальників, не складає їхні CLI-команди й не вибирає механізм реєстрації. Поля профілів і чинні ID збережено.

Тут клієнтський адаптер керує локальною реєстрацією. Процес `mcp-connect serve <profile-ID>` — окремий транспорт, який запускає AI-клієнт. Його авторизація, доступ до сховища та відновлення сесій не входять до цього рефакторингу.

## Контракт операцій

```go
type ClientAdapter interface {
    ID() string
    Read(id string) (Registration, bool, error)
    Set(context.Context, RegistrationRequest) error
    Detect() string
    Settings(id string) (ClientSettings, error)
}
```

[Код контракту](../internal/core/client_adapter.go) визначає нормалізовану реєстрацію та намір програми. Спільні типи не містять TOML-таблиць, plugin manifests чи прапорців CLI постачальника. `Detect` знаходить клієнта; `Settings` повертає дані для відображення; `Read` і `Set` читають та застосовують реєстрацію. Успішний `Set` має зберегти чужі записи й перевірити потрібний результат.

## Межі відповідальності

- `client_adapter.go`: контракт, упорядкований реєстр і спільні перевірки належності та результату. `Registration` — нормалізовані дані; теги серіалізації належать приватним структурам адаптерів.
- `client_defaults.go`: явне створення адаптерів, назви та прив'язка до наявних полів вибору в профілі. Прив’язки визначаються за сталим ID адаптера; порядок визначень керує лише звітами. Відсутні, невідомі та повторні елементи складу відхиляються.
- `integration.go`, `client_state.go`: пошук адаптера, незалежне застосування та повторення дій, статуси й збереження вимкненого профілю до очищення.
- `adapter_codex.go`: пошук Codex, npm entrypoint, команди, читання TOML прямих MCP-записів.
- `adapter_claude.go`: пошук Claude Code, npm entrypoint, команди з user scope, читання JSON і спроба відновлення попереднього запису після невдалої заміни.
- `adapter_claude_desktop.go`: пошук програми та шляхів, JSON, збереження сторонніх полів, перевірка одночасних змін і атомарний запис.
- `adapter_chatgpt.go`: пошук програми, plugin manifests, назви marketplace, записи належності, перевірки керованих шляхів, команди встановлення/видалення та їхні відповіді. Він не читає конфігурацію Codex.
- `openai_store.go`: фізичне сховище OpenAI, перевірка активності плагіна й marketplace, спільний пошук CLI та npm launcher. Він не реалізує реєстрацію та не залежить від клієнтських адаптерів.
- `client_command.go`, `client_environment.go`, `client_paths.go`: спільний запуск, оточення та файлові операції без знань про постачальника. Адаптери задають власний npm entrypoint; Windows launchers не передаються командній оболонці.

`Set` отримує ID і назву профілю, шлях програми та бажаний стан. `Settings` повертає інструкції та дії для GUI; інтерфейс не зберігає шляхи реєстрації чи CLI-інструкції клієнтів. `Integrator.ChatGPTSetupURL` залишено як тонкий сумісний виклик. Невелика додаткова операція `ReadShared` зберігає семантику спільної реєстрації без перевірки назви постачальника в координаторі.

Реєстр зберігає порядок додавання, відхиляє повторні й невідомі ID та прив'язує вибір до полів профілю. Результати `Apply` незалежні: помилка одного клієнта не скасовує успішного налаштування іншого. Адресний Retry звертається лише до вказаних ID.

## Спільне сховище OpenAI

Codex і ChatGPT наразі використовують спільний фізичний конфігураційний файл і CLI launcher. `openai_store.go` відповідає за спільні шляхи, активність плагіна, перевірки marketplace, пошук і запуск виконуваного файла. ChatGPT створює цей невеликий backend безпосередньо та не залежить від `CodexAdapter`. Codex володіє форматом прямих MCP-записів і командами реєстрації та використовує лише спільні допоміжні функції шляхів і запуску. Для спільного статусу Codex отримує нормалізоване читання реєстрації ChatGPT.

Зміна лише плагінових полів зачіпає backend і його fixtures без змін адаптера Codex. Зміна маніфесту чи команди встановлення ChatGPT зачіпає його адаптер і fixtures. Зміна прямих MCP-записів Codex — адаптер Codex і його fixtures. Зміна формату всього фізичного сховища потребує оновлення спільного backend та кодеків цього файла. Ця спільна залежність явна й не поширюється на координатор, GUI чи сховище профілів. Універсального конфігураційного рушія чи динамічного завантаження адаптерів немає.

## Сумісність і захист

Виявлення означає, що програму знайдено, а не що її версію сертифіковано. `ClientState.Compatibility` залишається `unknown`: читання запису чи успішний CLI-виклик не засвідчує сумісність невідомої версії. Адаптери перевіряють відомі форми конфігурацій і відповідей. Некоректний конфіг, непідтримувана команда, змінена відповідь установлення або невдале підтвердження стану повертають помилку відповідного клієнта. Діагностика розрізняє скасування, таймаут, відсутній виконуваний файл і відмову в доступі. Інші помилки команд радять перевірити конфігурацію та версію клієнта й оновити MCP Connect або клієнт; довільний stderr не відображається. Матриці версій чи окремого compatibility framework немає.

Належність MCP-запису перевіряється за абсолютним шляхом програми й точними аргументами `serve <profile-ID>`. Чужі записи не замінюються й не видаляються. Desktop JSON зберігає сторонні значення. Записи належності плагіна, межі кешу та перевірки симлінків захищають керовані файли й каталоги. У конфігурації немає секретів. Формати профілю, транспорту, авторизації, сховища й відновлення сесій не змінено.

## Контрольні сценарії

| Зміна постачальника | Очікувані зміни реалізації |
|---|---|
| Синтаксис реєстрації Claude Code | Адаптер Claude Code і його fixtures/тести |
| Маніфест або команда встановлення ChatGPT | Адаптер ChatGPT і його fixtures/тести |
| Формат прямих MCP-записів Codex | Адаптер Codex і його fixtures/тести |
| Спільне сховище OpenAI / поля плагіна | Спільний backend і його fixtures/тести; зміна формату всього файла може зачепити кодеки записів |
| Новий клієнт | Новий адаптер і тести, явна композиція та вибір у GUI/профілі |

Додавання клієнта не потребує нової гілки реєстрації в координаторі чи змін наявних адаптерів. Збереження його вибору потребує явного рішення щодо профілю та GUI; цей рефакторинг не перебудовує сховище профілів. Ізоляція змін постачальника діє, доки спільний контракт залишається застосовним.

## Тести та перевірки

Репозиторій містить fixtures адаптерів і спільні контрактні тести. Нативний CI запускає unit-, контрактні та GUI-тести на всіх шести платформах і перевірку гонок на Linux AMD64. `.local/` залишається приватним допоміжним каталогом.

Тести композиції переставляють визначення та адаптери й перевіряють відповідність прапорців профілю сталим ID. Усі чотири адаптери проходять сценарії помилки зміни та невдалої перевірки результату. Desktop додатково перевіряє конкурентні зміни, збереження файла після помилки запису й перевірку видалення.

Кожен адаптер має власні fixtures конфігурацій і CLI. Спільні контрактні тести працюють лише з нормалізованими операціями. Fixture ChatGPT підставляє backend-операції й не залежить від TOML Codex. Наявні наскрізні регресійні тести також перевіряють справжнє спільне сховище.

Використовуйте `go test ./...`, `go test -race ./...`, `go vet ./...` та `go mod verify`. Тести встановлених CLI потребують `ONECMCP_TEST_CLIENT_CLIS=1`; вони ізолюють домашні каталоги й конфігурації в тимчасових папках. Тести системного сховища потребують окремого `ONECMCP_TEST_NATIVE_VAULT=1`. Деталі — [збирання та перевірки](BUILD.uk.md).

Кроскомпіляція підтверджує лише можливість зібрати Go-код; вона не підтверджує графічний запуск, встановлення чи поведінку на іншій ОС.

## Додавання клієнта

1. Реалізуйте контракт у невеликому адаптері; залиште його формати, команди, пошук і перевірки сумісності всередині.
2. Додайте fixtures адаптера та виконайте спільні поведінкові тести.
3. Додайте явну прив'язку в `client_defaults.go`: сталий ID, назву та функцію вибору. Покажіть вибір у GUI; якщо його потрібно зберігати, явно визначте поле профілю.
4. Перевірте незалежність помилок Apply/Retry та збереження чинних реєстрацій. Не додавайте перевірку постачальника в `Integrator`.

Для поточного випуску [нативний CI 0.4.13](https://github.com/SeredaLabs/mcp-connect/actions/runs/39031665077) пройшов усі шість цілей збирання та оновлення. Окремі локальні тести перевірили контракт, установлені CLI, GUI та macOS Keychain, зокрема з перевіркою гонок. Невідомі версії клієнтів залишаються `unknown`.
