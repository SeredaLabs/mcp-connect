# 🛠️ Збирання MCP Connect

🌐 [English](BUILD.md) · **Українська**

[← Огляд](INSTALL.uk.md) · [Авторизація](AUTHENTICATION.uk.md) · [Безпека](SECURITY.uk.md) · [Збирання](BUILD.uk.md)

Збирайте пакунок для відповідної ОС із версіями залежностей, зафіксованими в `go.mod` і `go.sum`.

## 📋 Вимоги

| Платформа | Інструменти |
|---|---|
| macOS | Go 1.27.2+, Xcode Command Line Tools |
| Windows AMD64 | Go 1.27.2+, Git Bash, MSYS2 UCRT64 GCC |
| Windows ARM64 | Go 1.27.2+, Git Bash, MSYS2 CLANGARM64 clang |
| Ubuntu 24.04 | Go 1.27.2+, компілятор C, бібліотеки для графічного інтерфейсу |

Для Windows потрібен `7z` або `zip` у PATH. Установіть `CC` у повний шлях до відповідного компілятора MSYS2, щоб випадково не використати інший компілятор із PATH.

Для Ubuntu встановіть:

```sh
sudo apt-get install build-essential dpkg-dev libgl1-mesa-dev libegl1-mesa-dev xorg-dev libxkbcommon-dev libwayland-dev wayland-protocols
```

## 🛠️ Збирання

```sh
bash scripts/build.sh
```

Пакунки зберігаються в `dist/`. До них входять виконуваний файл або `.app`, українська інструкція, ліцензія програми та повідомлення про ліцензії залежностей.

[Процес збирання](https://github.com/SeredaLabs/mcp-connect/actions/workflows/build.yml) збирає шість цільових платформ на відповідних ОС: для кожної створює portable-архів та установник, загалом 12 пакунків. Також перевіряє цілісність залежностей, статичний аналіз та відомі вразливості. Він не виконує підписування видавцем чи нотаризацію.

Пакування Windows створює вбудовану іконку через `go-winres v0.3.3`. Цей інструмент завантажується Go лише для збирання й не входить до програми.

## 📦 Установники

Після `bash scripts/build.sh` виконайте `bash scripts/package-installer.sh` на відповідній ОС. macOS використовує вбудовані `pkgbuild` і `productbuild`, Linux — `dpkg-deb`, Windows — Inno Setup 7.1.0 (задайте `ISCC` як шлях до `ISCC.exe` або додайте `iscc` у PATH). Компілятор Windows потрібен лише для збирання. CI завантажує офіційний випуск і перевіряє зафіксований SHA-256.

CI встановлює 0.4.13, оновлює її до поточної збірки на всіх шести платформах, перевіряє командний режим, а також видалення й очищення ярликів на Windows/Linux. Це не підтверджує графічний запуск чи довіру до видавця. Установники зберігають профілі й секрети та не реєструють MCP-клієнти під час встановлення.

## Перевірки та зміни інтеграцій

[Нативний запуск 0.4.13](https://github.com/SeredaLabs/mcp-connect/actions/runs/39031665077) пройшов на всіх шести платформах. Це перевірки пакунків, оновлення та встановленого CLI, а не підтвердження ручної роботи GUI.

Після отримання копії репозиторію виконайте:

```sh
go test ./...
go test -race ./...
go vet ./...
go mod verify
```

Тести в `internal/core` та `internal/gui` зберігаються в репозиторії. Нативний CI запускає `go test ./... -count=1` на всіх шести платформах і перевірку гонок на Linux AMD64. `.local/`, допоміжні перевірки та згенеровані пакунки залишаються ігнорованими. Реліз 0.4.13 передує цьому кроку CI; його історичний запуск вище перевіряв пакунки та виконував статичний аналіз.

Тести встановлених клієнтів потребують `ONECMCP_TEST_CLIENT_CLIS=1` і використовують тимчасові домашні каталоги та конфігурації. Тести системного сховища потребують `ONECMCP_TEST_NATIVE_VAULT=1` і створюють та видаляють вигадані тестові секрети. Обидва набори вмикаються явно локально; для них потрібні відповідно встановлені CLI та доступне сховище ОС.

Перед зміною клієнтської інтеграції прочитайте [контракт і межі адаптерів](INTEGRATIONS.uk.md). Команди, формати, шляхи та тестові fixtures належать відповідному адаптеру. Координатор, GUI та формат профілів не мають змінюватися, доки спільний контракт залишається застосовним.

## Діагностика нативного запуску GUI

CI запускає готовий виконуваний файл із порожньою тимчасовою конфігурацією та вимкненою перевіркою оновлень. Linux використовує Xvfb/software OpenGL і потребує видимого вікна. macOS перевіряє вікна через CoreGraphics, Windows — через нативне перебирання вікон. Видиме вікно та живий процес підтверджують лише запуск. Обмеження графіки VM або непідтверджене вікно Windows записуються як недоступний/непідтверджений результат, із попередженням і окремим звітом `gui-check-*`; це ніколи не зараховується як успішний GUI-тест. Неочікуване завершення спричиняє помилку перевірки. Звіти містять журнал запуску без справжніх профілів чи облікових даних.

Ці перевірки не замінюють тестування взаємодії на фізичних пристроях. Mesa/Xvfb потрібні лише середовищу CI та не входять до пакунків програми.
